		The solution models the problem as recursively building palindromes by merging strings from both ends.
		Each state is defined by a **leftover substring** (`cur`) and a **direction flag** (`dir`) indicating 
		whether this leftover lies on the left or right side of the growing palindrome. Starting from any string `S[i]`,
		the algorithm tries to merge it inward with every other string `S[j]`—character by character from the outer edges—until a mismatch occurs.
		If the merge succeeds, the unmatched portion (the “leftover”) becomes the new state,
		possibly on the opposite side depending on which string was consumed first. 
		If the leftover is already a palindrome (or empty), the recursion stops with zero extra cost; otherwise,
		the algorithm continues recursively, summing the corresponding string costs. To prevent redundant work,
		results are memoized by `(cur, dir)`, and cycles are guarded against with an `inStack` check. 
		The minimal cost across all valid merging sequences that form a palindrome is tracked, and if no combination works, 
		`-1` is returned. In essence, this approach efficiently simulates the process of extending a string from either side until 
		a palindrome is achieved, exploring all combinations through memoized DFS.
